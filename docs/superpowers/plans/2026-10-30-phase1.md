# Phase 1 implementation plan

Goal: implement the supplied specification in docs/requirements.md.
Architecture: independent Nest API and BullMQ worker share validated contracts and streaming ingestion. PostgreSQL owns schema, import state, and publication transactions; Redis is a recoverable delivery mechanism. Next.js consumes authenticated HTTP endpoints. Superset is separate.

1. Define strict shared schemas, immutable import contracts and trusted artifact templates.
2. Build platform migrations, authentication, proposal review/handoff and catalog verification API.
3. Implement deterministic streaming profiling, COPY staging, full validation and transactional idempotent publication; wire worker.
4. Build functional role-aware admin UI covering the workflow and records.
5. Add Compose, read-only reporting and Superset bootstrap, migration release gate, operating documentation.
6. Install pinned dependencies, typecheck/build, run unit and real PostgreSQL integration tests and Playwright; record actual benchmark and remaining limitations.

Review focus: untrusted identifiers and paths; stale approvals/contracts; retries after commit; blank and duplicate CSV values; unauthorized dataset and secret access.

Implementation choices: local durable volume storage; AES-GCM secret encryption with external environment key; database sessions; explicit per-user dataset grants for non-admins. No cloud resources are provisioned.
